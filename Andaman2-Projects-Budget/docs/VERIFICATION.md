# ผลการตรวจสอบรุ่น 3.0

- npm test ผ่าน 14 รายการ ครอบคลุมตัวคำนวณรายงานเดิม ระบบ Apps Script เดิม และ workflow โครงการ / งบประมาณใหม่
- ทดสอบบนฐานข้อมูลจริงใน transaction แล้ว rollback ทั้งชุด: เสนอ → อนุมัติ → สร้างโครงการ → จัดสรร 800 บาท → ขอเบิก 200 บาท → อนุมัติ → บันทึกจ่าย → ส่งรายงาน → ตรวจรับ
- หลัง rollback ตรวจแล้วว่าแหล่งงบและโครงการจริงยังเป็น 0 รายการ และมีเฉพาะ Admin เริ่มต้น 1 บัญชี ไม่มีบัญชีทดสอบหรือรายการเงินทดสอบค้าง
- ตาราง pm_* ทั้ง 13 ตารางเปิด RLS ผู้ใช้ authenticated อ่านตามสิทธิ์ และเขียนตรงไม่ได้ Public RPC เป็น SECURITY INVOKER ส่วนการทำธุรกรรมมีการตรวจสิทธิ์ภายใน schema ส่วนตัว
- Storage bucket เป็น private จำกัด 10 MB และตรวจหน่วยงาน / โครงการ / ผู้แนบ การจัดการสมาชิกตรวจ token และบทบาท Admin ใน Edge Function
- ตรวจเมนูและ workflow ผ่าน Browser ในโหมดสาธิตครบวงจร โครงการที่ทดสอบมีวงเงินจัดสรร 12,000 บาท จ่ายจริง 3,000 บาท และรายงานแสดงตรงกัน หลังตรวจรับโครงการเป็น 100%
- ตรวจรายงานตัวอย่าง 10 หน้า และตรวจจอมือถือ 390 px ไม่มีเนื้อหาล้นออกนอกหน้า ตารางกว้างเลื่อนได้ในกรอบ เมนูมือถือและปุ่มยกเลิกทำงาน
- การทดสอบเลือกไฟล์ผ่าน Browser จบด้วยเครื่องมือหมดเวลา จึงยังไม่ยืนยันการอัปโหลด / ดาวน์โหลดไฟล์ผ่านหน้าจอแบบครบวงจร ไม่ได้ทดสอบรหัสผ่านจริงของผู้ใช้หรือสร้างบัญชีใหม่ให้บุคคลจริงเพื่อทดสอบ

Supabase security advisor ไม่พบคำเตือนใหม่ของตารางหรือ RPC ระบบ pm_* หลังติดตั้ง ยังมีรายการเดิมของระบบบุคลากรเรื่อง public SECURITY DEFINER 9 ฟังก์ชัน และการตั้งค่า leaked password protection ของ Auth ที่ปิดอยู่ ไม่แก้การตั้งค่าของระบบเดิมโดยอัตโนมัติ

เอกสารสำหรับผู้ดูแลที่ต้องตรวจเพิ่ม:

- https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable
- https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection

ข้อจำกัดการเผยแพร่: เว็บไซต์ Sites คงสิทธิ์ส่วนตัวตามเดิม บัญชี Supabase ไม่ได้ให้สิทธิ์เข้าชม Sites อัตโนมัติ การเปิดใช้กับบุคลากรหลายคนต้องกำหนดสิทธิ์เข้าชมเว็บไซต์ หรือใช้ชุด dist บนโฮสต์ของสถาบันตามคู่มือ

## เพิ่ม Andaman Report v2.0 ในเมนูรายงานและการติดตาม

- เมนูรายงานเปิดแท็บ Andaman Report v2.0 โดยตรง พร้อมสร้างรายงาน เปิดร่างเดิม นำเข้า / สำรอง JSON และพิมพ์ PDF
- เพิ่มแท็บติดตามรายงานโครงการ โดยคงการดึงชื่อโครงการ งบจัดสรร และยอดจ่ายจริงเข้าสู่รายงาน
- ทดสอบสร้างรายงานใหม่ สลับแท็บ ค้นหาจากแถบหลัก แล้วเปิดร่างกลับมา ข้อมูลไม่หาย
- ทดสอบออกไปเมนูโครงการแล้วกลับมารายงาน พบฉบับที่บันทึกก่อนออกจากเมนู
- ร่าง v2.0 ในระบบจริงใช้พื้นที่เก็บเดิม ส่วนโหมดสาธิตแยกร่างตัวอย่างออกต่างหาก
- ชุดทดสอบเดิมทั้ง 14 รายการผ่านหลังปรับ และไม่ได้เปลี่ยนฐานข้อมูลหรือสิทธิ์ผู้ใช้

## ปรับบันทึกข้อความและเพิ่มคู่มือกรอกข้อมูล

- ใช้หัวข้อส่วนราชการแบบบรรทัดเดียว ยกเลิกการบังคับแบ่งคำและคอลัมน์กว้างคงที่
- หัวส่วนราชการ ที่ วันที่ เรื่อง และเรียนตามด้วยช่องว่างแบบไม่ตัดบรรทัดจำนวน 2 ตัว ก่อนข้อความจริง ตรวจจาก DOM ใน Browser ครบทั้ง 5 หัวข้อ
- ชื่อบันทึกข้อความ 29 pt / line-height 35 pt หัวข้อมูล 20 pt เนื้อความ 16 pt และย่อหน้า 25 mm ส่วนเรียนใช้ตัวอักษรเนื้อความ
- เรื่องอ้างอิงชื่อโครงการ และคงลำดับ ส่วนราชการ → ที่ / วันที่ → เรื่อง → เรียน → เนื้อความ → ลงนาม → ความเห็น
- ตรวจตัวอย่างที่มีชื่อโครงการ เลขหนังสือ วันที่ งบ 50,000 บาท ร้อยละความสำเร็จ และระดับคุณภาพแล้ว บันทึกข้อความพร้อมช่องลงนามและความเห็นอยู่ครบ 1 หน้า ไม่มีเนื้อหาล้นพื้นที่พิมพ์
- เพิ่มเมนูคู่มือการกรอกข้อมูลให้สมาชิกที่ใช้งานได้ทุกบทบาท เป็นคู่มือสาธิตแบบอ่านอย่างเดียว ไม่เปลี่ยนสิทธิ์ฐานข้อมูล
- คู่มือหลักมี 23 หัวข้อพร้อมช่องกรอก ตัวอย่าง ขั้นตอน และสิ่งที่ต้องตรวจ ค้นคำว่าส่วนราชการแล้วพบหัวข้อบันทึกข้อความที่เกี่ยวข้องในสิทธิ์เจ้าหน้าที่
- ตัวรายงาน v2.0 ใช้คู่มือรายงาน 6 ส่วนร่วมจากข้อมูลคู่มือชุดเดียวกัน
- สร้างและตรวจ START_HERE.html ซึ่งเปิดคู่มือกรอกข้อมูล / คู่มือนำระบบไปใช้จริงได้ และตรวจสคริปต์ในคู่มือ HTML ทั้งสองไฟล์แล้ว
- ชุดทดสอบ 14 รายการผ่านหลังปรับ รวมการรวมไฟล์รายงานสำหรับ Apps Script ที่มีคู่มือเพิ่มเข้ามา
- ตรวจโปรเจกต์ Supabase เดิมมีสถานะ ACTIVE_HEALTHY ไม่เปลี่ยน schema ข้อมูลการเงิน สมาชิก หรือสิทธิ์ของระบบเดิมในงานแก้รูปแบบและคู่มือครั้งนี้


## ปรับระยะบรรทัด ANDAMAN REPORT และสารบัญ

- เนื้อความ ย่อหน้า ตาราง หมายเหตุ คำบรรยายภาพ และส่วนลงนามใช้ระยะบรรทัด 1.0 เนื้อความหลักและตาราง 16 pt
- หัวข้อใหม่ขนาด 16 pt ใช้ระยะก่อนหน้า 8 pt ทำให้เริ่มห่างจากบรรทัดก่อนหน้า 1.5 เท่า ย่อหน้าเนื้อความ 25 mm
- คงหัวบันทึกข้อความ 29 pt / Exactly 35 pt และหัวข้อมูล 20 pt ตามแนวทางหนังสือภายใน ระหว่างย่อหน้าบันทึกเพิ่ม 6 pt
- ลบหมายเหตุเรื่องเลขหน้าอ้างอิงออกจากสารบัญ สารบัญยังเป็นรายการเรื่องและหน้าโดยไม่ใช้ตาราง
- ตรวจ Browser ในตัวรายงานที่ฝังในเมนูรายงานและการติดตาม: line-height เนื้อความ 21.3333 px เท่ากับ font-size 16 pt; หัวข้อใหม่มี margin-top 10.6667 px หรือ 8 pt; ช่องว่างหลังหัวบันทึกครบ 2 ตัวทั้ง 5 ช่อง
- รายงานตัวอย่างปกติจัดได้ 9 หน้า ไม่มีเนื้อหาล้นหน้า บันทึกข้อความพร้อมความเห็นอยู่ครบหน้าเดียว
- เพิ่มข้อความอภิปรายผลสมมติ 30 ย่อหน้าทางหน้าจอ: จัดได้ 12 หน้า ข้อความครบตรงต้นฉบับ ไม่มีหัวข้อค้างท้ายหน้า ไม่มีเนื้อหาล้น สารบัญขยับหน้าสรุปผลเป็น 9 และภาคผนวกเป็น 10 ตามจริง แล้วคืนข้อความตัวอย่างเดิม
- npm test ผ่าน 14 รายการ และสร้างคู่มือกรอกข้อมูลกับชุด Apps Script ใหม่ ไม่เปลี่ยน schema หรือข้อมูลจริงของ Supabase


## ปรับหัวบันทึกข้อความและหัวข้อผลประเมิน

- หัวบันทึกใช้โครงสร้างแถวร่วมกัน ส่วนราชการ–ที่ / วันที่–เรื่อง มีช่องว่างระหว่างแถว 6 pt และความสูงขั้นต่ำ 24 pt ข้อมูลยาวยังตัดบรรทัดตามจริงโดยไม่ตัดข้อความทิ้ง
- ตรวจรายงานตัวอย่างใน Browser พบระยะจากตำแหน่งหัวส่วนราชการถึงที่ และจากที่ถึงเรื่องเท่ากัน 40 px ทั้งสองช่วง
- หัวข้อ 6 และ 7 เป็น H3 เหมือนกัน: 16 pt (21.3333 px), น้ำหนัก 700, ชิดซ้าย และ line-height 1.0
- ส่วนค่าเฉลี่ย สูตร และเกณฑ์แปลผลเป็น line-height 1.5 (32 px ที่ตัวอักษร 16 pt)
- คงเส้นตารางผลประเมินตามคำแก้ไขล่าสุดของผู้ใช้ ตรวจเซลล์ตารางยังเป็น border 1px solid
- รายงานตัวอย่างยังมี 9 หน้า บันทึกข้อความอยู่ครบหน้าเดียว และไม่พบพื้นที่เนื้อหาล้นหน้ากระดาษ
- ตรวจ JavaScript และสร้าง Apps Script ใหม่ ชุดทดสอบ gas-bundle ผ่าน อัปเดตคู่มือและแพ็กเกจต้นฉบับโดยไม่เปลี่ยนฐานข้อมูลหรือข้อมูลจริง

- เพิ่มพื้นที่คอลัมน์ค่าเฉลี่ยและป้องกันตัดบรรทัดตัวเลข เพื่อให้ค่าเช่น 4.60 แสดงครบในบรรทัดเดียวโดยไม่ลดขนาดตัวอักษรหรือเอาเส้นตารางออก


## ตารางค่าเฉลี่ย S.D. และบรรยายผลอัตโนมัติ

- ตารางหัวข้อ 7 มี 4 คอลัมน์: รายการประเมิน, ค่าเฉลี่ย (x̄), S.D., แปลผล พร้อมแถวภาพรวมทุกข้อ และคงเส้นตาราง
- คำนวณ S.D. แบบกลุ่มตัวอย่างจากความถี่คะแนน 1–5 รายข้อและรวมคำตอบทุกข้อ; คำตอบน้อยกว่า 2 แสดง — แทนศูนย์หรือ NaN
- ค่า S.D. ภาพรวมเป็นการกระจายของคำตอบทุกข้อรวมกัน ไม่ใช่ S.D. ของคะแนนเฉลี่ยรายบุคคล ซึ่งข้อมูลแบบความถี่ไม่สามารถระบุได้
- ลบสูตรและข้อความเกณฑ์แปลผลจากหน้ารายงาน ใช้ข้อความเริ่ม จากตาราง พบว่า… สรุปภาพรวม ตามด้วยชื่อข้อและค่าเฉลี่ยสูงสุดและต่ำสุด พร้อม S.D.
- ข้อที่ไม่มีผู้ตอบไม่ใช้จัดอันดับ กรณีค่าเฉลี่ยที่แสดงทศนิยม 2 ตำแหน่งเท่ากันแสดงทุกข้อที่เท่ากันตามลำดับข้อเดิม รองรับทุกข้อเท่ากัน มีข้อมูลข้อเดียว และไม่มีข้อมูล
- เพิ่ม S.D. แบบอ่านอย่างเดียวในหน้ากรอกผลประเมิน อัปเดตอัตโนมัติจากจำนวนผู้ตอบเดิม ไม่เพิ่มช่องให้พิมพ์ค่าทางสถิติเอง
- npm test ผ่านทั้ง 20 รายการ รวมการทดสอบสถิติและบทสรุปใหม่ 6 รายการ เช่น ตัวอย่างคะแนน 1–5 อย่างละหนึ่งมี S.D. = sqrt(2.5), และ S.D. รวมคำนึงถึงความแตกต่างระหว่างข้อ
- ตรวจ Browser จริง: รายงานตัวอย่าง 9 หน้า ไม่มีพื้นที่เนื้อหาหรือตัวเลขล้น ตาราง 4 คอลัมน์ ภาพรวม x̄ 4.53 / S.D. 0.62; สูงสุดข้อ 1 x̄ 4.60 / S.D. 0.62; ต่ำสุดข้อ 5 x̄ 4.47 / S.D. 0.63; บทสรุปตรงตารางและคงระยะบรรทัด 1.5
- อัปเดตคู่มือและชุด Apps Script ไม่เปลี่ยน schema สิทธิ์ หรือข้อมูลจริงของ Supabase

อ้างอิง S.D. แบบกลุ่มตัวอย่าง: https://www.itl.nist.gov/div898/software/dataplot/refman2/ch2/standevi.pdf
