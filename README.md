## โครงสร้างสถาบัน

ตั้งต้นตามข้อบังคับการจัดตั้งและแบ่งหน่วยงาน พ.ศ. 2568 จำนวน 5 ส่วนงานและ 7 สถานศึกษา

- สำนักงานผู้อำนวยการสถาบัน
- สำนักพัฒนายุทธศาสตร์และความร่วมมืออาชีวศึกษา
- สำนักพัฒนากิจการนักศึกษาและกิจการพิเศษ
- ศูนย์วิจัยและพัฒนาการอาชีวศึกษา
- อาชีวศึกษาบัณฑิต
- วิทยาลัยเทคนิคระนอง
- วิทยาลัยเทคนิคพังงา
- วิทยาลัยเทคนิคภูเก็ต
- วิทยาลัยอาชีวศึกษาภูเก็ต
- วิทยาลัยเทคนิคกระบี่
- วิทยาลัยเทคนิคตรัง
- วิทยาลัยการอาชีพตรัง

Admin เพิ่มกลุ่มงานย่อยภายใต้หน่วยงานแม่ได้ตามคำสั่งมอบหมาย เช่น งานการเงิน / บัญชี งานพัสดุ และงานแผนงาน ไม่สมมติว่ากลุ่มงานที่ผู้ดูแลเพิ่มเป็นส่วนงานตามข้อบังคับโดยอัตโนมัติ ระบบป้องกันโครงสร้างวนกลับ

## ลำดับการใช้งานจริง

1. Admin เพิ่มแหล่งงบใน “แหล่งงบประมาณ” ระบุปีงบประมาณ พ.ศ. หมวดงบ วงเงิน และเลขอ้างอิงในหมายเหตุ
2. เจ้าหน้าที่เลือก “เสนอโครงการ” กรอกชื่อ หน่วยงาน วัตถุประสงค์ รายละเอียด งบที่ขอ วันดำเนินงาน และกำหนดส่งรายงาน เลือกบันทึกร่างหรือส่งพิจารณา
3. ผู้บริหารเปิดข้อเสนอ เลือกอนุมัติ / ส่งกลับแก้ไข / ไม่อนุมัติ พร้อมเหตุผล เมื่อตอบอนุมัติระบบสร้างโครงการและรหัสให้อัตโนมัติ วงเงินอนุมัติต้องไม่เกินที่เสนอ
4. Admin เปิด “จัดสรรงบโครงการ” เลือกโครงการและแหล่งเงินในปีเดียวกัน จะจัดสรรหลายแหล่งเงินหรือหลายครั้งก็ได้ แต่รวมไม่เกินวงเงินโครงการและวงเงินแหล่งเงิน
5. เจ้าหน้าที่สร้างคำขอเบิกจ่าย เลือกแหล่งเงินที่จัดสรรให้โครงการ ระบุวัตถุประสงค์และจำนวนเงิน
6. ผู้บริหารอีกคนอนุมัติหรือไม่อนุมัติคำขอ ผู้เสนอ / ผู้ขอไม่สามารถอนุมัติรายการของตนเอง แม้เป็น Admin
7. เมื่อจ่ายเงินจริงแล้ว ผู้มีสิทธิ์ใน “บันทึกจ่ายจริง” บันทึกเลขที่หลักฐานและวันที่จ่าย รายการต้องอนุมัติแล้ว วันที่ต้องอยู่ในปีงบประมาณและไม่เป็นอนาคต การบันทึกนี้เก็บสถานะและหลักฐาน ไม่ใช่การโอนเงินผ่านธนาคาร
8. เจ้าหน้าที่อัปเดตความก้าวหน้าและแนบไฟล์ขออนุญาต / หลักฐานโครงการ ผู้บริหารตรวจรับหรือส่งกลับแก้ไข
9. เปิด “รายงานและการติดตาม” → “จัดทำรายงาน” ชื่อ หน่วยงาน งบจัดสรร และยอดจ่ายจริงจะมาจากฐานข้อมูล กรอกผลดำเนินงาน ผู้ตอบแบบสอบถาม คะแนน ตัวชี้วัด AAR บันทึกข้อความ และภาพกิจกรรม
10. กด “บันทึกเข้าโครงการ” เพื่อเก็บร่างออนไลน์ หรือ “ส่งรายงานเพื่อตรวจรับ” เมื่อตรวจรับแล้วโครงการเปลี่ยนเป็นเสร็จสิ้นและความก้าวหน้า 100% ถ้าส่งกลับแก้ไข เจ้าหน้าที่แก้และส่งใหม่ได้

ควรเพิ่มผู้บริหารอย่างน้อยหนึ่งคนแยกจากผู้จัดทำก่อนเริ่มขั้นตอนอนุมัติ เพราะระบบใช้หลักแยกผู้จัดทำและผู้อนุมัติ

## หลักการคำนวณงบและสถานะ

- วงเงินอนุมัติโครงการเป็นเพดานการจัดสรร ไม่ใช่ยอดจ่ายจริง
- แหล่งเงินยังไม่จัดสรร = วงเงินตั้งต้น − การจัดสรรให้โครงการ − คำขอส่วนกลางที่รออนุมัติ / อนุมัติ / จ่ายแล้ว
- โครงการเบิกได้อีกจากแต่ละแหล่งเงิน = งบที่จัดสรรจากแหล่งนั้น − คำขอจากแหล่งนั้นที่รออนุมัติ / อนุมัติ / จ่ายแล้ว
- เมื่อส่งคำขอจะกันวงเงินทันที หากไม่อนุมัติจะคืนวงเงินที่กันไว้ รายการอนุมัติยังไม่ถือเป็นยอดจ่ายจริง
- ยอดจ่ายจริงนับเฉพาะสถานะ “จ่ายแล้ว” งบส่วนกลางใช้จากยอดแหล่งเงินที่ยังไม่ได้จัดสรรเท่านั้น ไม่หักซ้ำจากวงเงินโครงการ
- Dashboard ใช้ปีงบประมาณไทย 1 ตุลาคม – 30 กันยายน ตามเวลา Asia/Bangkok มีกราฟจ่ายจริงสะสมและสัดส่วนการใช้จ่าย เจ้าหน้าที่เห็นภาพรวมเฉพาะโครงการในขอบเขตของตน
- รายงานอ่านยอดจัดสรรและยอดจ่ายจริงจากฐานข้อมูลซ้ำขณะบันทึก จึงไม่เชื่อยอดเงินที่แก้เองจากเบราว์เซอร์
- คำสั่งบันทึกใช้ transaction, ล็อกรายการงบ และรหัสคำขอป้องกันการบันทึกซ้ำ การแก้รายการตรวจสอบเวอร์ชันด้วย

## เอกสาร แบบฟอร์ม และรายงาน A4

คลังแบบฟอร์มและไฟล์โครงการรองรับ PDF, DOC, DOCX, XLSX, JPG, PNG, WebP ไม่เกิน 10 MB ต่อไฟล์ เก็บใน bucket ส่วนตัว สมาชิกดาวน์โหลดผ่านลิงก์ชั่วคราว 120 วินาที โหมดสาธิตรองรับไฟล์ไม่เกิน 1.5 MB และเก็บเฉพาะเบราว์เซอร์

รายงาน A4 คงรูปแบบที่ปรับไว้ก่อนหน้า: โลโก้อยู่เหนือชื่อรายงาน สารบัญไม่ใช้ตาราง คำว่า “เรื่อง” ชิดซ้าย เลขหน้าด้านบนขวา 16 pt ใช้คำว่า “ค่าเฉลี่ย” บันทึกข้อความและช่องความเห็นผู้บริหาร ภาคผนวกเอกสารตามรายการเดิม และภาพกิจกรรม สูงสุด 20 ภาพ คำนวณสารบัญจากหน้าที่จัดจริง

หน้าตัวอย่างรายงานเลือก “พิมพ์ / บันทึก PDF” ตั้ง A4, Scale 100% และปิด Headers and footers ของเบราว์เซอร์ ก่อนบันทึกควรตรวจตัวอย่าง โดยเฉพาะเมื่อฟอนต์ของอุปกรณ์ต่างกัน ตารางและข้อความยาวแบ่งหน้าอัตโนมัติ

ร่างที่กำลังแก้ไขบันทึกในเบราว์เซอร์ ส่วนปุ่ม “บันทึกเข้าโครงการ” บันทึกขึ้น Supabase หากเปลี่ยนอุปกรณ์ให้บันทึกเข้าโครงการก่อนออก เมนู “รายงานและการติดตาม” เปิดแท็บ “Andaman Report v2.0” โดยตรง สำหรับสร้างรายงาน เปิดร่างเดิม สำรอง / นำเข้า JSON คำนวณค่าเฉลี่ย และพิมพ์ PDF ส่วนแท็บ “ติดตามรายงานโครงการ” ใช้รายงานที่เชื่อมกับโครงการและงบประมาณ สลับแท็บแล้วร่างที่กำลังแก้ยังคงอยู่ ก่อนออกไปเมนูอื่นระบบจะบันทึกร่างให้ ไม่แปลงหรือเขียนทับร่างเดิมโดยอัตโนมัติ

## การแจ้งเตือนและข้อมูลสรุป

กระดิ่งแสดงข้อเสนอและคำขอเบิกจ่ายรอพิจารณา รายงานรอตรวจรับ และโครงการเลยกำหนดส่งรายงานตามปีที่เลือก ข้อมูลออนไลน์ปรับปรุงทุก 30 วินาทีเมื่อเปิดหน้าใช้งานและไม่ได้แก้ไขในหน้าต่าง ข้อมูลหลังบันทึกจะโหลดใหม่ทันที การแจ้งเตือนรุ่นนี้เป็นภายในแอป ยังไม่มีการส่งอีเมล LINE หรือ push ขณะปิดเว็บ

ส่งออก CSV สรุปโครงการ / งบ / สถานะรายงาน และประวัติการดำเนินการที่แสดง (1,000 รายการล่าสุด) ได้ เปิดด้วย Microsoft Excel, LibreOffice Calc หรือ Google Sheets ไฟล์ใช้ UTF-8 พร้อม BOM และป้องกันข้อความที่ขึ้นต้นเป็นสูตร

## ติดตั้งใหม่ใน Supabase และโฮสต์ของสถาบัน

ขั้นตอนนี้สำหรับย้ายไปโปรเจกต์ / โดเมนอื่น ระบบที่ลิงก์ด้านบนติดตั้งไว้แล้ว

1. สร้างหรือเลือกโปรเจกต์ Supabase เปิด SQL Editor แล้วรัน `supabase/pm_setup.sql` ทั้งไฟล์ ตั้งค่าเฉพาะตาราง pm_* และ bucket andaman-pm-files
2. สร้างบัญชี Admin ใน Authentication → Users จาก Dashboard ของ Supabase แล้วเปิด `supabase/bootstrap_admin.sql` เปลี่ยนอีเมลตัวอย่างให้ตรงบัญชีจริง รันเพื่อเพิ่มสิทธิ์ Admin เริ่มต้น คำสั่งนี้ไม่ทราบและไม่เปลี่ยนรหัสผ่าน
3. เปิด Settings / API Keys ของโปรเจกต์ คัดลอก Project URL และ publishable key ไปใส่ `dist/config.js` ห้ามใส่ secret key หรือ service_role key ในไฟล์หน้าเว็บ
4. ใน Edge Functions สร้างฟังก์ชันชื่อ `pm-members` และใช้โค้ด `supabase/functions/pm-members/index.ts` ฟังก์ชันตรวจ `auth.getUser(token)` และสมาชิก Admin ที่ยังใช้งานภายในโค้ด จึงตั้งค่า gateway Verify JWT เป็น false เพื่อรองรับกุญแจ JWT แบบใหม่ โดยยังต้องส่ง token ผู้ใช้และผ่านการตรวจ Admin ทุกครั้ง
5. ฟังก์ชันใช้ environment มาตรฐาน SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY ที่ Supabase จัดให้ หากใช้ secret key แบบใหม่แทนให้ตั้ง PM_SUPABASE_SECRET_KEY ที่ฝั่ง Edge Function เท่านั้น
6. สำหรับโดเมนใหม่ ตั้ง environment PM_ALLOWED_ORIGINS เป็น origin เต็ม เช่น `https://projects.example.ac.th` หากมีหลายโดเมนคั่นด้วยจุลภาค ห้ามใส่ path หรือเครื่องหมาย / ท้าย origin ปัจจุบันอนุญาตโดเมน Sites ที่ติดตั้งไว้แล้ว
7. นำไฟล์ภายใน `dist/` ทั้งหมดขึ้น web hosting ที่เป็น HTTPS เช่น เว็บเซิร์ฟเวอร์สถาบันหรือ GitHub Pages หน้าเริ่มต้นต้องเข้าถึง index.html และโฟลเดอร์ report-editor ได้
8. ถ้าใช้ GitHub Pages ให้นำชุดโค้ดขึ้น repository แล้วเลือก Settings → Pages → Source เป็น GitHub Actions ใช้ workflow ที่รวมไว้ การเข้าไฟล์เว็บยังต้องล็อกอิน Supabase ก่อนอ่านข้อมูลจริง
9. ถ้าใช้ Sites ส่วนตัว สมาชิก Supabase ที่เพิ่มใหม่จะยังไม่ผ่านสิทธิ์เข้าชมของ Sites โดยอัตโนมัติ ต้องกำหนดผู้เข้าชมเว็บไซต์ตามนโยบายสถาบัน หรือเผยแพร่ชุด dist บนโฮสต์ของสถาบันที่สมาชิกเข้าถึงได้ก่อน โดยคง Supabase login และ RLS ไว้
10. ทดสอบด้วย Admin เพิ่มผู้บริหารและเจ้าหน้าที่จริง จากนั้นทดลองข้อเสนอวงเงินเล็กที่สถาบันอนุญาต ตรวจสิทธิ์ข้อมูลต่างหน่วยงาน และกระบวนการตรวจรับก่อนเริ่มรอบงานจริง

ตัวอย่าง config สำหรับโปรเจกต์อื่น:

```javascript
window.ANDAMAN_CONFIG = {
  supabaseUrl: 'https://YOUR_PROJECT_REF.supabase.co',
  supabasePublishableKey: 'YOUR_PUBLISHABLE_KEY',
  membersFunction: 'pm-members',
  loginAliases: {}
};
```

ถ้าต้องการชื่อผู้ใช้สั้นสำหรับ Admin ให้กำหนด loginAliases ให้ชี้อีเมลบัญชี Admin จริง การกำหนด alias เป็นเพียงการแปลงชื่อเข้าระบบ ไม่ได้ให้สิทธิ์ Admin สิทธิ์จริงอ่านจาก pm_members

## โครงสร้างการเชื่อมต่อ

หน้าเว็บ JavaScript เรียก Supabase Auth เพื่อยืนยันตัวตน ใช้ token ผู้ใช้เรียกตารางที่มี RLS เพื่ออ่านข้อมูล และเรียก RPC pm_action สำหรับทุกการบันทึก ตารางไม่ให้ authenticated เขียนตรง RPC ตรวจบทบาท เมนู หน่วยงาน สถานะ เวอร์ชัน วงเงิน และบันทึก audit ใน transaction เดียว

ไฟล์แนบเก็บใน Supabase Storage แบบ private แบ่ง path ตามโครงการและผู้แนบ ตัวจัดทำรายงานทำงานใน iframe จาก origin เดียวกัน ติดต่อหน้าแม่ด้วย postMessage ที่ตรวจ origin และหน้าต่างต้นทาง หน้าแม่บันทึกภาพและรายงานด้วยสิทธิ์ของผู้ใช้

เมนูสมาชิกเรียก Edge Function pm-members ผ่าน token ผู้ใช้ ฟังก์ชันตรวจว่าเป็น Admin ก่อนใช้กุญแจฝั่งเซิร์ฟเวอร์สร้าง Auth user หรือเพิ่มผู้ใช้ที่มีอยู่แล้ว ไม่ส่งรหัสผ่านหรือกุญแจเซิร์ฟเวอร์กลับมายังหน้าเว็บ

CSV ดาวน์โหลดจากข้อมูลที่ผู้ใช้มีสิทธิ์อยู่แล้ว สามารถนำไปเปิดใน Excel / Google Sheets ได้ ระบบหลักรุ่น 3 ไม่ต้องเชื่อม Google Sheets เพื่อทำงาน

## Google Apps Script / Sheets / Drive ของรุ่นรายงานเดิม

ชุด `apps-script/` และ `supabase/setup.sql` / `report-sheet-sync` เป็นส่วนของระบบรายงานเดิม เก็บไว้เพื่อใช้ย้อนหลัง อ่านการติดตั้งละเอียดที่ `docs/LEGACY_REPORT_V2.md` ตัวแอปหลักรุ่น 3 ใช้ pm_reports และ andaman-pm-files จึงไม่ส่งรายการโครงการหรืองบประมาณไป Sheets อัตโนมัติผ่าน bridge รุ่นเดิม

ถ้าใช้ Apps Script เป็นตัวจัดทำรายงานเดี่ยว ให้คัดลอก apps-script/Code.gs, Index.html และ manifest ไปยัง Apps Script ตามคู่มือเดิม ไม่ให้นำ dist/index.html ของแอปหลักไปวางแทน Apps Script เพราะหน้าแอปหลักต้องใช้ไฟล์หลายไฟล์และ iframe ส่วนรายงาน

## ทดสอบและดูโค้ดทั้งหมด

ติดตั้ง Node.js รุ่น 22 ขึ้นไป เปิด terminal ในโฟลเดอร์โปรเจกต์:

```bash
npm ci
npm run build:gas
npm test
npm run build:user-guide
npm run build:handbook
```

Node.js ใช้เตรียมไฟล์และทดสอบเท่านั้น เว็บไซต์ static ไม่ต้องมี Node server ขณะใช้งานจริง หลังแตก ZIP เปิด INSTALLATION_AND_CODE.html ในเบราว์เซอร์ เลือกแท็บ “โค้ดทั้งหมด” ค้นหาไฟล์ ดูชื่อโปรแกรม และคัดลอกโค้ดทั้งไฟล์ได้

ทดสอบฐานข้อมูลด้วย PGlite รวมการแบ่งหน่วยงาน ห้ามเขียนตารางตรง ห้ามเจ้าหน้าที่อนุมัติ ห้ามอนุมัติตนเอง กันงบคำขอ ป้องกันจัดสรร / เบิกเกิน การบันทึกซ้ำ เวอร์ชันเก่า รายงานยอดเงินอ้างอิงฐานข้อมูล และห้ามลดสิทธิ์ Admin คนสุดท้าย นอกจากนี้ทดสอบ workflow บน Supabase จริงใน transaction ที่ rollback ทั้งหมด ไม่มีข้อมูลทดสอบค้าง

ตรวจหน้าจอผ่าน Browser ในโหมดสาธิตครบเสนอ → อนุมัติ → สร้างโครงการ → จัดสรร → ขอเบิก → อนุมัติ → จ่ายจริง → รายงาน → ตรวจรับ ทดสอบจอมือถือกว้าง 390 px โดยไม่มีเนื้อหาล้นหน้าจอ รายงานตัวอย่างจัดได้ 10 หน้า ตัวเลขจัดสรรและจ่ายจริงตรงกัน ไม่ได้ทดสอบล็อกอินด้วยรหัสผ่านจริงของผู้ใช้หรือสร้างบัญชีบุคคลอื่นเพื่อทดสอบ

เพิ่มแล้ว: งบส่วนกลาง / สาธารณูปโภค โครงสร้างหน่วยงานแม่–กลุ่มงานย่อย ประวัติผู้ดำเนินการ ป้องกันวงเงินซ้ำ การแจ้งเตือนเลยกำหนดส่งรายงาน และการส่งกลับแก้ไข
